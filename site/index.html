Sheet

A spreadsheet that opens your Excel workbook, lets you work in it, and gives it back without wrecking it.

Open a workbook with pivot tables, charts and macros we cannot even display. Change one cell. Save.

You get back a file where every part we did not touch is byte-for-byte identical — the pivot definitions, the drawings, the conditional-format rules, all of it.

Every other tool routes your file through its own model and silently discards whatever that model does not cover. “I opened it in the free one and it wrecked my file” is the single biggest reason people never leave Excel. It does not happen here.

What you can do today

  • Open and save .xlsx — formulas, formats, styles, merged cells, charts
  • Type, edit, copy, cut and paste — pasted formulas shift their references, and the plain values go to Excel or an email
  • Insert and delete rows and columns — every formula in the whole workbook follows
  • Bold, italic, colour, fills, borders, currency, percent, alignment
  • Undo and redo everything, including formatting

Deck

Slides where a number on the slide is the number in the sheet — not a copy of it that was true last Tuesday.

Put a chart and a headline figure on a slide, then change a cell in the spreadsheet next to it.

The bar grows, the axis rescales, the percentage recomputes and the sentence re-typesets — with no synchronisation code anywhere, because a slide object and a cell are the same kind of thing depending on the same range.

Every deck you have ever made goes stale the moment the model changes, and someone has to notice. This one cannot: there is nothing to refresh.

What you can do today

  • Text boxes that hold a value or a formula — =SUM(main!B4:B6) on a slide is a live figure
  • Bar, line, area and pie charts bound to a range of cells
  • Number formats on a slide, so a KPI reads 45.2% and not 0.45200000001
  • Add, delete and reorder slides; nudge, resize and recolour objects

One document, not two apps that talk

Sheet and Deck are usable on their own, or side by side over a single document — and that document saves to a single file.

A Miscellany document is a graph of nodes, so it does not care which app made them. A file can hold a workbook and a deck together, and the app invented next year gets saved the day it exists.

It stores what you typed, never what was computed. A file that caches a result next to the formula that produced it can hold the two in disagreement; ours cannot, because it does not contain the answer. Opening a document recalculates it.

One node per line, so a document diffs, merges and blames in Git like source code. Human-readable. Nothing in the format can execute — there is no script, macro or external reference for it to become.

Why it behaves differently

We never inherit someone else's model

A library that reads spreadsheets has already decided what a spreadsheet is — and quietly drops whatever did not fit that decision. So we read the file format ourselves, straight from the published specification. That is slower to build and it is the entire reason your pivot tables survive.

The numbers are checked against Excel's own answers

A spreadsheet file stores the result Excel calculated next to every formula. That turns any real workbook into an exam we did not write. Across the test set — including a 353,000-node energy model with 39 sheets — we reproduce 223,596 of 223,601 results exactly, and match all 1,790 cells where Excel itself reports an error.

Everything is made of the same thing

Underneath is one dependency graph. A cell that adds up a column and a chart that plots one are the same kind of object depending on the same range — which is why a chart here shows what your sheet says now, not what it said when the file was last saved.

The second app cost a fraction of the first

That claim is easy to make and easy to check, so here it is checked: Deck is 712 lines, of which the entire startup file is 34. It has undo, redo, a command palette, keyboard shortcuts, a generated toolbar and autosave — and implements none of them, because those belong to the shell every app is hosted in. Every button in both apps is generated from one list of 54 commands, which is also what generates the API.

Honest about what is missing

Software that overstates itself wastes your time twice — once when you try it and once when you have to undo it. So:

Not a full Excel

76 formula functions, not 500. No pivot tables, macros or array formulas — they are preserved perfectly on save, just not editable.

Deck cannot open PowerPoint

It reads and writes Miscellany documents. .pptx import and export is not built yet.

Sheet's charts are read-only

A chart already in your workbook renders from live data, but you cannot create one there yet. In Deck you can.

No collaboration

No accounts, no server, no sharing. That is a deliberate choice, not a gap we forgot.

The API is generated, not served

The HTTP routes and AI tool definitions are real and you can view them — but nothing answers them yet.

Early

A young project, tested hard — 679 automated checks plus four suites that drive the real interface in a real browser — but not yet used by many people.
